# 我会牢牢记住你：微信私聊适配 R2 安装修复版

版本：`2.6.5+weixin.2.2`，日期：2026-11-08。
基于上游 `f16d64365f23514cd8faa459899ec92cf94e2925`（2.6.5）。
这是第三方实验适配，不是 menglimi 正式发布。使用 AstrBot 4.29.4 源码和真实微信事件类做本地测试，
没有登录真实微信，也没有通过微信服务端进行收发。

## 桌面版安装修复

原 R1/R2 声明了错误的宿主运行依赖，可能在桌面版额外安装 AstrBot 并与宿主冲突。
此版移除运行期 SDK 安装，保留版本兼容校验。已出现重复导入或启动失败时，
先使用单独交付的离线恢复工具处理，再安装本版；仅上传新 ZIP 不能移走已有误装副本。
此前的 R2 微信测试通过不代表该安装路径已验证。

## R2复查与升级

复查的是此前实际交付的R1 ZIP，不是仅凭仓库版本号推测。
新增用例在R1复现4项失败；R2修复了这些边界：

- 平台实例已删除、不可解析或缺少宿主平台解析器时，带scope的联动读取返回空／不可用，
  不再退回仅按用户ID读取其它窗口。
- 默认仍使用平台实例ID作为内部账号键；同时接受注册微信适配器当前 `account_id` 的已核验别名。
  不接受任意自称的账号，不从聊天正文或显示名推断身份。
- 联动候选先按Bot、人格及平台预筛，再限制条数，然后继续原有可见性和生命周期检查。
  避免其它人格的近期记录占满候选，导致当前人格有记忆却召回不到。
- 微信事件即使上报真实Bot账号，记忆owner仍使用同一个平台实例键，不拆分或迁移既有记忆库。

R1不是因为陪伴插件变成R2就必然不能使用；此次升版是因为发现了实际缺口。
R2不修改数据库结构，不清空历史，不修改上游的总结、遗忘、去重合并算法。
过去已混写或合并的记录不会自动拆分；需要在记忆面板核对归属后人工处理。
summary仍是同一私聊窗口的统计，包含窗口内不同人格；本轮可注入内容会按当前人格过滤。

已装R1可按下文备份后替换同名插件；未装可直接安装当前 plugin-only 版。
本次联动验证使用之前交付的陪伴R2 `7.1.6+weixin.2`，不是现场手工修改过的代码。
模型沿用你现有DeepSeek配置，本包不会添加或重新启用Ollama，也不自动配置Embedding提供商。

## 改动范围

- 声明支持个人微信 `weixin_oc` 私聊，保留原QQ声明和全部界面。
- 微信事件使用平台实例 ID 作为 Bot 身份，封装层漏掉 self_id 时不会借用其它在线 Bot 的身份。
- 复用原有私聊采集、记忆写入、召回、模型请求前注入和管理面板。
- 与7.x陪伴插件联动读取微信记忆时，绑定到完整私聊窗口，再执行原有可见性、ACL、Bot所有者、
  人格和有效期检查；微信联动统计按完整私聊窗口计算。其它平台保持原兼容路径。
- 没有修改数据库结构、长期记忆算法、采样参数或用户人格，没有改动 AstrBot 宿主。

原插件已有通用私聊消息入口，因此这次适配比陪伴插件的微信改动少。
本包不是微信登录插件，不需要配置微信 API 地址或 token。

## 安装

本次交付分为两个独立 ZIP。`plugin-only.zip` 只供 AstrBot 上传安装，无需解压。
`astrbot-desktop-recovery-tool.zip` 是单独的离线恢复工具，不作为插件上传，也不随插件安装执行。
插件包不含 CMD、恢复脚本或开发测试文件；运行功能需要的 docs/contracts 完整保留。

1. 确认你的 AstrBot 为4.29.4，个人微信扫码连接能正常回复。
2. 如果安装过原版记忆插件，先导出／备份它的数据和配置。
   通常是 `data/plugin_data/astrbot_plugin_memory_companion` 及对应插件配置；
   如果自定义了数据位置，也要备份那个目录。可停机备份整个 `data`。
3. WebUI → 插件 → 从本地上传，选择交付的 ZIP，不用解压。
   保留插件ID `astrbot_plugin_memory_companion`，同名安装替换代码；不要先卸载并删除记忆。
4. 等待依赖检查和加载结束，必要时重启 AstrBot，确认版本显示 `2.6.5+weixin.2.2`。
5. 在个人微信所使用的 AstrBot 配置中启用此插件，并打开“我会牢牢记住你／她记得的人”页面。
6. 为微信会话选择爱弥斯人格。初次保持插件默认配置，先验收，再调整总结／Embedding模型。

无需再次发送新的“绑定记忆插件”口令。它通过当前微信事件识别用户、Bot和会话。
之前的 `我会永远陪着你 爱弥斯` 是陪伴插件的绑定命令，不是本插件的安装步骤。

## 和前一个陪伴包一起用

- 陪伴：`astrbot_plugin_private_companion`，已验证的配套版本 `7.1.6+weixin.2`。
- 记忆：本包 `astrbot_plugin_memory_companion`，`2.6.5+weixin.2.2`。
- 两个插件安装在同一 AstrBot 实例，个人微信只连接一次。
- 保留默认的陪伴桥接开关，两个插件加载后，Memory会向陪伴的外部记忆注册表登记读取／统计能力。
- 陪伴负责角色状态、日程、主动联系；本插件负责自己的长期记忆和检索注入。

当前桥接仍声明 `handles_model_memory=False`，所以本包作为外部记忆源参与，
不会自动接管或替换陪伴7.x自己的记忆库，也不会自动迁移旧记忆。
只需保留原来的爱弥斯人格，不必重复粘贴到记忆插件。

## 首次验收

1. 微信发送 `/mcomp status`，检查插件状态；命令前缀以你AstrBot的实际配置为准。
2. 发送：`请记住，我喜欢喝茉莉花茶。`。模型应调用记忆写入工具，只有返回成功才算保存。
3. 在记忆面板找到这条记录，核对微信平台、私聊窗口、Bot所有者和人格。
4. 用 `/new` 新建对话，再问：`我喜欢喝什么茶？`。
   新建对话用于排除仅靠当前聊天历史答对的情况，不要使用清空／删除记忆功能。
5. 如果希望检查保存来源，可以用 `/mcomp search 茉莉花茶` 或面板检索。
6. 想测试自动沉淀时，多聊几轮，确认时间线有原文记录，再观察阶段总结。
   自动总结不是每条消息立刻生成，且需要可用的模型提供商。

微信用户 ID 往往是一长串字符，不是你的手机号或普通微信号。
不要把它手动改成QQ号，也不要为了共用记忆打开跨平台身份合并。
换微信账号时，用新的平台实例 ID 和对应绑定，避免沿用另一个账号的上下文。

## 限制

- 不增加主动消息或语音发送能力，也不延长微信会话凭证有效期。
- 不会从微信服务器拉取全部历史聊天；已有历史导入中的NapCat／OneBot读取仍然只适用于QQ。
  微信从安装后收到的消息开始记录；文件上传导入仍按原功能人工核对归属。
- 纯文字模型不会因此获得识图能力；复杂微信附件、引用和转发未做真实服务端联调。
- 没有自动配置Embedding、总结、云端备用模型；这些仍取决于原插件和AstrBot配置。
- 没有自动合并旧QQ记忆和微信记忆，不保证其它AstrBot版本兼容。
- 其它原版桥接协议、Bot Personal档案能力和所有界面组合并非全部联调通过。

## 更新与回滚

不要点原仓库的一键更新覆盖实验版；如果界面提供自动更新开关，请先关掉。
回滚时恢复正式版插件代码及备份配置，保留数据库。若要恢复数据快照，先停机并核对数据位置。
本包没有新增数据库schema，但新微信记录与权限仍需要支持微信的版本处理。

测试范围与结果见 `WEIXIN_OC_TEST_RESULTS.md`。
